# 汎用 Target の指摘コードと書き換え方

Target が ScalarDB 以外（PostgreSQL・Oracle・MySQL・DuckDB・SQL Server など SQLGlot の方言）のときに、レポートの「指摘」列と「指摘の集計」表に出るコードの意味と、次に何をするかをまとめる。レポートの WARN / ERROR を利用者に説明するとき、ERROR の文を書き換えるときに読む。ScalarDB を Target にしたときのコードは `scalardb-grammar.md` にある。

変換先の能力（どの構文・関数を持つか）は PostgreSQL 16、Oracle Database 23ai、MySQL 8.4、DuckDB 1.5 で動かして決めた。SQL Server・SQLite・Snowflake・BigQuery は公開文書に基づく。この 8 方言以外の Target では、「Target に無い構文」の検査をしない。

---

## 素の sqlglot.transpile が素通りさせるもの

SQLGlot は、Source の構文を Target が持っていなくても、例外を出さずにそのまま出力することがある（SQLGlot 30.18 で確認）。

| 入力 | 変換 | sqlglot.transpile の出力 | 何が起きるか |
|---|---|---|---|
| `WHERE ROWNUM <= 5` | Oracle → PostgreSQL | そのまま | 実行時に列が無いエラー |
| `WHERE e.deptno = d.deptno(+)` | Oracle → PostgreSQL | `WHERE e.deptno = d.deptno` | 外部結合が内部結合になり、**結果が静かに変わる** |
| `CONNECT BY PRIOR empno = mgr` | Oracle → PostgreSQL | そのまま | 構文エラー |
| `VALUES (emp_seq.NEXTVAL)` | Oracle → PostgreSQL | そのまま | 実行時エラー |
| `TRUNC(hiredate, 'MM')` | Oracle → MySQL | `DATE(hiredate)` | 月初めでなく日単位の切り捨てになり、**結果が静かに変わる** |
| `empno / 4`（整数どうし） | PostgreSQL → Oracle | そのまま | 切り捨てが小数になり、**結果が静かに変わる** |
| `empno DIV 4` | MySQL → Oracle | `CAST(empno / 4 AS INT)` | 切り捨てが四捨五入になる（7499 DIV 4 が 1875） |
| `DATE '1981-01-01'` | PostgreSQL → Oracle | `CAST('1981-01-01' AS DATE)` | Oracle の既定の日付書式に依存して失敗する |
| `` `emp` `` | MySQL → Oracle | `"emp"` | 大文字小文字を区別する名前になり、表が見つからない |

`(+)` だけは `unsupported_level=ErrorLevel.RAISE` で検出できる。残りは SQLGlot が未対応と認識していないので、どのエラーレベルでも検出されない。このスキルは前処理で直せるものを直し、直せないものを下のコードで報告する。

## 指摘コードを出さずに直すもの

前処理で直し、レポートには何も出ない。

| 対象 | 条件 | 書き換え |
|---|---|---|
| 再帰 CTE | Target に合わせて | PostgreSQL・MySQL・DuckDB には `RECURSIVE` を付ける。Oracle からは外し、再帰 CTE に列名の並び（`WITH t(n) AS ...`）を付ける |
| `FROM dual` | Target が Oracle 以外 | 落とす。MySQL は `DUAL` を持つが、SQLGlot が引用符で囲むので表として解決されない |
| `TRUNC(date, 'MM')` の書式 | Source が Oracle | `MM`・`YYYY`・`DD`・`HH24`・`Q`・`IW` などを標準の単位名（`MONTH`・`YEAR` …）にする。直さないと PostgreSQL と DuckDB は拒み、MySQL では日単位の切り捨てになる |
| 日付・日時の文字列リテラル | Target が Oracle | `DATE '1981-01-01'` や `'1981-01-01'::date` を `TO_DATE('1981-01-01', 'YYYY-MM-DD')`、日時を `TO_TIMESTAMP(..., 'YYYY-MM-DD HH24:MI:SS')` にする |
| `INTERVAL '6 months'` | Target が Oracle | 単位を単数形にする（SQLGlot は `MONTHS` のまま出し、Oracle は拒む）。月・年の加算は `ADD_MONTHS(d, n)` にする（単数形にするだけでは 1 月 31 日 + 1 か月で失敗する） |
| `a DIV b`（MySQL の整数除算） | Target が Oracle | `TRUNC(a / b)`。SQLGlot の `CAST(... AS INT)` は四捨五入になる |
| `DATEDIFF(a, b)` | Source が MySQL、Target が Oracle | `(TRUNC(a) - TRUNC(b))`。日付の文字列リテラルは `TO_DATE` にする |
| `AUTO_INCREMENT` | Source が MySQL、Target が Oracle | `GENERATED BY DEFAULT AS IDENTITY`。PostgreSQL・SQL Server 向けは SQLGlot が IDENTITY 列にする。DuckDB 向けは SQLGlot が拒むので ERROR `UNSUPPORTED`（シーケンスと `DEFAULT nextval('seq')` で書き直す） |
| `DISTINCT ON` | Source が PostgreSQL、Target が Oracle | SQLGlot の `ROW_NUMBER()` への書き換えが作る `_` で始まる別名を Oracle は拒むので、先頭に `x` を付ける。DuckDB は `DISTINCT ON` をそのまま受け付ける |
| バッククォート・角括弧で囲んだ識別子 | Source が MySQL / SQL Server | 予約語でなければ引用符を外す。予約語なら引用符を残し、Target の畳み方（Oracle・Snowflake は大文字、PostgreSQL は小文字）にそろえる。例: MySQL の `` SELECT `ename`, `order` FROM `emp` `` → Oracle の `SELECT ename, "ORDER" FROM emp` |
| `GROUP BY a WITH ROLLUP` | Source が MySQL、Target が MySQL 以外 | `GROUP BY ROLLUP (a)`。書き換えられない形が残ると ERROR `WITH_ROLLUP` |
| 別名の無い派生表 | すべて | `subq1` のような別名を付ける（MySQL と SQL Server は別名を要求する） |
| MERGE の `UPDATE SET t.v = s.v` | Target が PostgreSQL / DuckDB / SQLite | 表名の修飾を外す |

Source と Target が同じ方言のときは、整形し直して読み直せるかだけを確かめる。

## 指摘コード

### 自動で直したことの記録（INFO）と、その条件

| コード | 重要度 | 意味 | 次の手 |
|---|---|---|---|
| `ORACLE_JOIN_MARK` | INFO | Oracle の `(+)` を `LEFT JOIN` に書き換えた（`sqlglot.transforms.eliminate_join_marks`）。`(+)` の付いた表が FROM の先頭にあれば、先に記号の付かない表と入れ替える | なし |
| `ORACLE_JOIN_MARK` | ERROR | 書き換えられない。同じ 2 表の間で向きが混ざっている、1 つの表を 2 つの表に外部結合している、両辺に `(+)` がある（Oracle 自身も ORA-01416・ORA-01417・ORA-01468 で拒む形） | 明示的な `JOIN` で書き直す |
| `ROWNUM` | INFO | `WHERE ROWNUM <= n` を `LIMIT n`（`ROWNUM < n` は `LIMIT n-1`、SQL Server は `TOP n`）にした | なし |
| `ROWNUM` | WARN | 同じ書き換えだが、SELECT に ORDER BY か FOR UPDATE がある。Oracle は ORDER BY より**前に** ROWNUM を適用するので、元の文は「任意の n 件を並べ替えたもの」。FOR UPDATE と LIMIT ではロックされる行が方言で違う | 元の意図を確かめる。上位 n 件が意図なら変換後の `ORDER BY ... LIMIT n` のほうが正しい |
| `ROWNUM` | ERROR | 上限が整数リテラルでない。DISTINCT・GROUP BY・HAVING・集約関数・ウィンドウ関数のある SELECT（ROWNUM は入力の行、LIMIT は出力の行を数える）。WHERE の単純な上限以外（射影、OR の中、`ROWNUM > n`）に残った | 先に絞る副問い合わせ（`FROM (SELECT ... LIMIT n)`）か `ROW_NUMBER() OVER (...)` で書き直す |
| `HINT` | INFO | オプティマイザヒント（`/*+ ... */`）と、MySQL 以外への `STRAIGHT_JOIN` を外した。実行計画にしか効かず、結果は変わらない | なし |
| `CONNECT_BY` | INFO | Target が DuckDB で、SQLGlot が階層問合せを再帰 CTE に書き換えた。1 表の `START WITH ... CONNECT BY PRIOR ...` だけで、WHERE・結合・`FROM dual`・`NOCYCLE`・`ORDER SIBLINGS BY`・`SYS_CONNECT_BY_PATH`・`CONNECT_BY_ISLEAF` / `CONNECT_BY_ISCYCLE` を含まない形に限る（それ以外は ERROR） | なし |

### 型に依存するもの

列の型が分かって初めて直せる。型は入力スクリプト内の `CREATE TABLE` と `--schema` から取る。

| コード | 重要度 | 意味 | 次の手 |
|---|---|---|---|
| `DIVISION` | INFO | Source は整数どうしの除算で小数部を切り捨て（PostgreSQL・SQL Server・SQLite・Redshift・Trino など）、Target は小数を返す。両辺が整数と分かったので、Target で切り捨てる形にした: Oracle / Snowflake は `TRUNC(a / b)`、MySQL は `TRUNCATE(a / b, 0)`、DuckDB は `a // b`、BigQuery は `DIV(a, b)` | なし |
| `DIVISION` | WARN | 同じ組み合わせで、除算の型が分からない。上の 5 方言以外の Target では型が分かっても書き換えないので、こちらになる | 表定義を渡して再変換する。SQLGlot 自身の模倣（`CAST(a / b AS INT)`）は四捨五入になるので使わない |
| `DATE_ARITH` | INFO | Target が MySQL で、日付どうしの引き算を `DATEDIFF(a, b)` にした（MySQL で日付どうしを引いても日数にならない。`'1981-02-01' - '1981-01-31'` は 70） | なし |
| `DATE_ARITH` | WARN | Target が MySQL で、片方が日付・もう片方の型が分からない引き算がある。または Source が Oracle・Target が MySQL / Oracle 以外で、日付の足し引きがある（Oracle では小数つきの日数。Target では型によって整数の日数、interval、型エラーになる。`SYSDATE - 7` は PostgreSQL で `CURRENT_TIMESTAMP - 7` になり失敗する） | 式を見せて、日数か interval かを確かめる。n 日前は `INTERVAL` で書く |

### Oracle と Target で意味が変わるもの（書き換えない）

Source が Oracle、Target が Oracle 以外のとき。

| コード | 重要度 | 意味 | 次の手 |
|---|---|---|---|
| `EMPTY_STRING` | WARN | 空文字 `''` がある。Oracle は `''` を NULL として扱い、Target は空文字のまま持つ。`= ''`・`IS NULL` と、INSERT した値の読み出しで結果が変わる | その列で空文字と NULL を区別しているか確かめ、`IS NULL` に直すか決める |
| `DATE_TIME` | WARN | `CREATE TABLE` に `DATE` 列がある。Oracle の DATE は時刻を持ち、Target の DATE は日付だけ | 時刻を使う列は `TIMESTAMP(0)` 相当の型にする |

### MySQL が返す値の違い（書き換えない）

Target が MySQL、Source が MySQL 以外のとき。

| コード | 重要度 | 意味 | 次の手 |
|---|---|---|---|
| `BOOLEAN_RESULT` | WARN | 真偽値の式を射影している。MySQL に真偽値の型は無く、TRUE / FALSE ではなく 1 / 0 で返る | 受け取る側が 1 / 0 を扱えるか確かめる |
| `DIV_PRECISION` | WARN | AVG か除算の結果をそのまま返している（ROUND・FLOOR・CEIL・TRUNC で包んだものは除く）。MySQL は小数桁を「被演算子の小数桁 + 4」で丸める（`div_precision_increment`。`DECIMAL(7,2)` の AVG は小数 6 桁） | 桁が要るなら `div_precision_increment` を上げるか DOUBLE に CAST する |
| `COLLATION` | WARN | Source が MySQL で、Target が大文字小文字を区別する（PostgreSQL・Oracle・DuckDB・SQLite・Snowflake）。英字を含む文字列リテラルとの `=`・`<>`・`LIKE`・`IN` は結果が変わりうる（MySQL の既定の照合順序は区別しない） | 区別しない比較を保つなら `--mysql-case-insensitive` で再変換する |
| `COLLATION` | INFO | `--mysql-case-insensitive` で、`LIKE` を `ILIKE`（Oracle は `LOWER(a) LIKE LOWER(b)`）に、`=`・`<>`・`IN` を両辺の `LOWER()` にした | 索引が使われなくなることがある。列ごとに照合順序を変えている場合は、その列だけ手で直す |

### 手作業が要るもの（ERROR）

| コード | 条件 | 意味と書き換え方 |
|---|---|---|
| `CONNECT_BY` | Target が Oracle・Snowflake 以外（DuckDB の単純な形は INFO） | 階層問合せ（`CONNECT BY` / `START WITH` / `PRIOR` / `LEVEL` / `SYS_CONNECT_BY_PATH`）。再帰 CTE に書き換える（下の例） |
| `SEQUENCE` | 下の表 | シーケンス。Target の採番機能に置き換える（下の表） |
| `ROWID` | Source が Oracle | 疑似列 `ROWID`。主キーで行を特定する形に書き換える |
| `KEEP` | Source が Oracle | `MAX(x) KEEP (DENSE_RANK FIRST ORDER BY y)`。ウィンドウ関数で書き換える（下の例） |
| `PLSQL` | Source が Oracle | `DBMS_OUTPUT`・`DBMS_LOB` など `DBMS_` で始まるパッケージの呼び出し。アプリケーション側の実装に置き換える。SQLGlot が標準の関数に写すもの（`DBMS_RANDOM.VALUE` → `RANDOM()`）は出ない |
| `PLSQL_BLOCK` | Source が Oracle | PL/SQL のブロック（`CREATE … PROCEDURE / FUNCTION / PACKAGE / TRIGGER`、`DECLARE` / `BEGIN` の無名ブロック）。始まる所から `/` だけの行（無ければスクリプトの終わり）までを 1 つとして扱い、変換しない。前に `;` で終わる SQL 文があっても同じ。plsql-migrate スキルで移行する |
| `PG_CATALOG` | Source が PostgreSQL | `::regclass`・`::regtype`・`::regproc`・`::oid` へのキャスト。Target には無い |
| `TRIGGER` / `PROCEDURE` / `FUNCTION` | すべて | トリガー・ストアドプロシージャ・ユーザー定義関数の DDL。方言差が大きく機械変換の対象外。Target の手続き言語で書き直す |
| `WITH_TIES` | Target が Oracle・PostgreSQL・SQL Server 以外 | `FETCH … WITH TIES`。`LIMIT n` にすると n 番目と同順位の行が落ちる。`RANK() OVER (ORDER BY …) <= n` で絞る形に書き直す |
| `UNSUPPORTED` | すべて | SQLGlot 自身が「Target では表現できない」と判断した（例: `PIVOT` / `UNPIVOT`、DuckDB への `AUTO_INCREMENT`）。メッセージに構文名が出る |

Oracle の `WITH FUNCTION … / PROCEDURE …`（WITH 句の中の PL/SQL）は、汎用 Target では `PARSE` の ERROR になる。関数をアプリ側か Target の関数に移してから変換する。

シーケンスの扱い:

| 入力 | Target | 結果 |
|---|---|---|
| `CREATE SEQUENCE` | PostgreSQL・Oracle・DuckDB・SQL Server・Snowflake | そのまま通す |
| `CREATE SEQUENCE` | MySQL・SQLite・BigQuery | ERROR |
| `seq.NEXTVAL` / `seq.CURRVAL`（Oracle） | Oracle 以外 | ERROR |
| `nextval('seq')` などの関数（PostgreSQL） | DuckDB | WARN（関数は同じ形で持つが、SERIAL 列が暗黙に作るシーケンスは作られない） |
| 同上 | PostgreSQL・DuckDB 以外 | ERROR |

| Target | 採番の代替 |
|---|---|
| PostgreSQL | `CREATE SEQUENCE` と `nextval('seq')`、または `GENERATED ALWAYS AS IDENTITY` |
| MySQL | `AUTO_INCREMENT` |
| SQL Server | `IDENTITY`、または `CREATE SEQUENCE` と `NEXT VALUE FOR` |

### Target に無い構文（ERROR）

生成した SQL に、Target が持っていない構文が残った。上に挙げた 8 方言の Target でだけ検査する。

| コード | 構文 | 持っている Target | 書き換え方 |
|---|---|---|---|
| `CONNECT_BY` | `CONNECT BY` | Oracle・Snowflake | 再帰 CTE |
| `MERGE` | `MERGE INTO` | PostgreSQL・Oracle・DuckDB・SQL Server・Snowflake・BigQuery | 存在確認と INSERT / UPDATE を 1 トランザクションで行う |
| `ON_CONFLICT` | `ON CONFLICT` | PostgreSQL・DuckDB・SQLite | Target の upsert 構文（`MERGE`、`ON DUPLICATE KEY UPDATE`） |
| `ON_DUPLICATE_KEY` | `ON DUPLICATE KEY UPDATE` | MySQL | Target の upsert 構文 |
| `RETURNING` | `RETURNING` | PostgreSQL・DuckDB・SQLite | 変更後に SELECT で読み直す |
| `SERIAL` | `SERIAL` / `BIGSERIAL` / `SMALLSERIAL` 型 | PostgreSQL・MySQL | IDENTITY 列 |
| `AUTO_INC` | `AUTO_INCREMENT` | MySQL | IDENTITY 列 |
| `AGG_FILTER` | `COUNT(*) FILTER (WHERE ...)` | PostgreSQL・DuckDB・SQLite・Oracle 23ai | `SUM(CASE WHEN ... THEN 1 END)` |
| `WITH_ROLLUP` | `WITH ROLLUP` | MySQL | `GROUP BY ROLLUP (...)` |
| `UPDATE_JOIN` | 結合つき UPDATE | MySQL | `UPDATE ... FROM` か相関サブクエリ |
| `UPDATE_LIMIT` | ORDER BY / LIMIT つき UPDATE・DELETE | MySQL | 主キーで対象行を絞る |
| `UPDATE_SELF_SUBQUERY` | 更新対象の表を読むサブクエリ（Target が MySQL のときだけ検査） | MySQL 以外 | サブクエリを派生表で包むか、先に読み取る |
| `DUPLICATE_ALIAS` | 1 つの FROM に同じ別名 | なし | 変換の結果が壊れている。元の SQL を見直す |

### 関数（WARN）

| コード | 意味 | 次の手 |
|---|---|---|
| `FUNC_PORTABILITY` | 出力に書かれた関数が Target の組み込み関数一覧に無い。一覧は PostgreSQL・Oracle・MySQL・DuckDB の分を実際のデータベースから取った（`scripts/catalogs/<方言>.json`）。表名・別名・型名の直後の括弧、`INDEX idx (col)`・`INSERT INTO t (col)`、`ON CONFLICT (...)`・`WITHIN GROUP (...)`、スキーマやパッケージで修飾された呼び出しは関数とみなさない。**利用者定義の関数も WARN になる** | Target に同じ関数を作るか、下の表のように書き換える |
| `FUNC_PORTABILITY` | 一覧の無い Target（SQL Server・Snowflake・BigQuery など）では、Source の関数名が元の名前のまま残っているかで判定する。Target が同名の関数を持っていても WARN になる（例: Oracle → SQL Server の `INITCAP`） | 同上 |
| `UNKNOWN_FUNC` | 一覧の無い Target で、生成した SQL を Target 方言で読み直したとき、SQLGlot が関数として認識できなかった | Target に同等の関数があるか確認する |

よく出る関数の書き換え:

| 関数（Oracle） | PostgreSQL | MySQL | SQL Server |
|---|---|---|---|
| `MONTHS_BETWEEN(a, b)` | `EXTRACT` と `AGE` で計算 | `TIMESTAMPDIFF(MONTH, b, a)` | `DATEDIFF(month, b, a)` |
| `ADD_MONTHS(d, n)` | `d + n * INTERVAL '1 month'` | `DATE_ADD(d, INTERVAL n MONTH)` | `DATEADD(month, n, d)` |
| `INITCAP(s)` | `INITCAP(s)`（あり） | なし（自前で組む） | なし |
| `LAST_DAY(d)` | `date_trunc('month', d) + interval '1 month - 1 day'` | `LAST_DAY(d)`（あり） | `EOMONTH(d)` |

| 関数（PostgreSQL） | Oracle | MySQL |
|---|---|---|
| `generate_series(a, b)` | `SELECT LEVEL + a - 1 FROM dual CONNECT BY LEVEL <= b - a + 1` | 再帰 CTE |

関数一覧は Target のバージョンに依存する。作り直し方は `operations.md`。

### 解析・生成・検証の段階（ERROR）

| コード | 意味 | 次の手 |
|---|---|---|
| `PARSE` | 元の SQL を Source 方言として読めなかった。空の文や、文でなく式として読めたもの（文の切れ目のずれ、PL/SQL の断片）も含む | `--source` が実際の方言と合っているか確かめる |
| `GENERATE` | SQLGlot の生成器が予期しない例外を出した。メッセージに例外の種類が出る | 文を手で書き換える |
| `ROUNDTRIP` | 生成した SQL を Target 方言として読み直せなかった。SQLGlot の生成器の不具合か、Target 方言の対応不足 | 同上 |

`TOKENIZE` と `INTERNAL` は Target によらない。SKILL.md の Step 3 と Error Handling を見る。

## 書き換えの例

階層問合せ（`CONNECT_BY`）:

```sql
-- Oracle
SELECT ename, LEVEL FROM emp START WITH mgr IS NULL CONNECT BY PRIOR empno = mgr;

-- PostgreSQL
WITH RECURSIVE tree AS (
  SELECT empno, ename, 1 AS level FROM emp WHERE mgr IS NULL
  UNION ALL
  SELECT e.empno, e.ename, t.level + 1 FROM emp e JOIN tree t ON e.mgr = t.empno
)
SELECT ename, level FROM tree;
```

`KEEP`:

```sql
-- Oracle
SELECT deptno, MAX(ename) KEEP (DENSE_RANK FIRST ORDER BY hiredate) FROM emp GROUP BY deptno;
-- 標準 SQL
SELECT DISTINCT deptno, FIRST_VALUE(ename) OVER (PARTITION BY deptno ORDER BY hiredate) FROM emp;
```

`PIVOT`（`UNSUPPORTED`）は `CASE` 式と集約に、`UNPIVOT` は列ごとの SELECT の `UNION ALL` に展開する:

```sql
SELECT deptno,
       SUM(CASE WHEN job = 'CLERK'   THEN sal END) AS clerk,
       SUM(CASE WHEN job = 'MANAGER' THEN sal END) AS manager
  FROM emp GROUP BY deptno;
```
