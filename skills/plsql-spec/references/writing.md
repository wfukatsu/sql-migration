# 仕様書の文章の書き方

事実の欄は「何が書いてあるか」を並べる。文章は「だから何が起きるか」を書く。読むのは、PL/SQL を
読まない人（業務担当、移行先の開発者）である。

## 全体の決まり

- **原文の位置を添える。** `` `pkg_order.pkb:42` `` の形で、ファイル名は事実の欄と同じに書く。
  `check` はこの形を拾い、その routine の範囲の外なら問題にする。行番号は原文を開いて確かめる
- **業務の言葉で書き、識別子は括弧で添える。** 「`v_amt` に `qty * prc` を入れる」ではなく
  「金額を 数量 × 単価 で求める」。表・列・エラーコード・状態の値（`'RECEIVED'`）は、検索できるよう
  原文の綴りのまま残す
- **条件の向きと境界を書く。** 「在庫が足りなければ断る」では足りない。「在庫数 < 数量なら断る。等しいときは通る」
- **書いていないことも仕様である。** 検査していない引数、受けていない例外、上限の無い待ちは、
  「無い」と書く。読む人は、あるものと思い込む
- **推測を事実の顔で書かない。** 原文から言えるのは「何をするか」までで、「なぜ」は言えない。
  コメントに理由が書いてあれば、コメントの引用として書く（コメントが処理と食い違うこともある）

## 節ごとに

### 概要（module）

何のためにあるかを 2〜4 文で。routine の一覧を言い直さない。package なら、セッションの間残る変数
（事実の欄の「package の変数・定数」）が振る舞いに効くかを必ず書く——同じ引数でも、前の呼び出しで結果が変わる。

### 動作

原文の順に、番号つきで。1 項目 = 業務上の 1 歩（SQL 1 文とは限らない）。

- 読む: どの表から、どの条件で、何を。1 行か複数行か。ロックするか（`FOR UPDATE` の `NOWAIT` / `WAIT n` /
  指定なし = 無期限に待つ）
- 書く: どの表に、どの値を。値がどこから来たか（引数 / 読んだ値 / 計算 / 採番 / 現在時刻）
- 分岐: 条件と、それぞれの道
- ループ: 何を 1 件ずつ回すか、順序は決まっているか（`ORDER BY` が無ければ決まっていない）、途中で抜ける条件
- 呼び出し: 呼び先の仕様への参照と、渡す値。呼び先の動作を写さない
- trigger: この routine の書き込みで発火するもの（事実の欄にある）と、その結果として起きること
- 戻り値と OUT 引数: どの道で何が返るか。何も代入されない道があれば、それも

### 業務ルール

動作から、規則として取り出せるものを 1 行ずつ。計算式、しきい値、状態の遷移（`'NEW'` → `'CONFIRMED'`）、
既定値、丸め。同じ規則が複数の routine にあれば、食い違っていないかを見る（食い違いは「確かめたいこと」）。

### エラーと例外

事実の欄の「上げるエラー」を 1 つも落とさない（`check` が見る）。表にして、コードごとに:

- **いつ**: 条件。ハンドラで言い換えているなら、元の例外（`NO_DATA_FOUND` → -20003）
- **そのときの書き込み**: それより前に書いたものがどうなるか

そのうえで、次を文章で書く:

- この routine が自分で ROLLBACK / SAVEPOINT に戻すか。しないなら、途中までの書き込みの始末は呼び出し側にある
- `WHEN OTHERS` があるか。あれば、何を握りつぶし、何を再送出するか。`WHEN OTHERS THEN NULL` は
  「すべての失敗を成功として返す」という仕様である。そのまま書く
- ハンドラが受けない例外は、そのまま呼び出し側に出ること

### 確かめたいこと

原文からは決められないことを、答える人が分かる問いにして書く。無ければ「なし」と書く（空にしない）。

- 意図が読めない処理（使われない引数、到達しない分岐、コメントと食い違う条件）
- 原文の外に答えがあること（呼び出し元は誰か、実データの件数、制約の有無）
- routine どうしの食い違い（同じ計算が 2 か所で違う丸め）

## 図

事実の欄には、IR から描いた図が入っている: routine ごとの**処理の流れ**、module の **routine と表**、索引の
**module と表**と**呼び出しと trigger**。これらは書き換えない。文章の側に足すのは、事実の欄の図では
伝わらないものである。

| 描くと伝わるもの | 記法 | 例 |
|---|---|---|
| 状態の遷移（`status` 列の値がどの routine でどう変わるか） | `stateDiagram-v2` | `NEW --> CONFIRMED: confirm` / `CONFIRMED --> CANCELLED: cancel（-20060 でなければ）` |
| 複数の routine・trigger にまたがる 1 つの業務の流れ | `sequenceDiagram` | 呼び出し元 → `cancel` → `orders` → trigger `trg_orders_audit` → `audit_log` |
| バッチの区切り（どこで COMMIT し、途中で止まると何が残るか） | `flowchart` | 100 件ごとの COMMIT と、SAVEPOINT に戻る道 |

- 図に描くのは原文から言えることだけである。遷移の矢印 1 本ごとに、根拠の位置（`` `ファイル:行` ``）を図の下に添える
- ラベルは引用符で囲む（`A["在庫数 < 数量"]`）。`<` `>` `"` をそのまま書くと図が壊れる（`#lt;` `#gt;` `#quot;`）
- 描いたら `mmdc -i <file.md> -o <scratch>/check.md -q` で確かめる。`mmdc` が無ければ、確かめていないと報告する
- 1 つの図に 15 個を超える箱を入れない。超えるなら分ける

## Oracle の振る舞いの落とし穴

書き間違えやすいところ。迷ったら、断定せず「確かめたいこと」に回す。

| 場面 | 正しい振る舞い |
|---|---|
| 例外で routine を抜けたときの書き込み | routine は自分では取り消さない。**PL/SQL の呼び出し元が例外を受ければ残る。誰にも受けられずクライアントまで出れば、Oracle がその呼び出しの変更を取り消す**（文単位のロールバック）。トランザクションは開いたまま |
| 例外で抜けたときの OUT 引数 | 呼び出し側の変数に値は戻らない（`NOCOPY` が付いていれば、途中の値が見えうる） |
| `SELECT … INTO` | 0 行で `NO_DATA_FOUND`、2 行以上で `TOO_MANY_ROWS`。集約関数（`COUNT`、`SUM`）だけの SELECT は 0 行にならない（`SUM` は NULL を返す） |
| function の中の `NO_DATA_FOUND` が SQL から呼ばれたとき | SQL 文の側では例外にならず、NULL が返ったように見える |
| `''`（空文字列） | NULL である。`= ''` は決して真にならない。`\|\|` は NULL を空として連結する |
| NULL を含む比較 | 真でも偽でもない。`IF x <> y` は片方が NULL なら通らず、`ELSE` に落ちる |
| `SQL%ROWCOUNT` / `SQL%NOTFOUND` | 直前の SQL 文のもの。UPDATE / DELETE が 0 行でも例外にならない——0 行を検査していなければ、「対象が無くても成功する」が仕様である |
| `FOR UPDATE` | ロックは COMMIT / ROLLBACK まで続く。指定なしは無期限に待つ。`NOWAIT` は ORA-00054、`WAIT n` は n 秒後に ORA-30006、`SKIP LOCKED` はロック中の行を飛ばす（結果が減る） |
| routine の中の `COMMIT` | 呼び出し側がそれまでに書いたものも確定する。カーソルループの途中の COMMIT は、途中で失敗すると確定済みと未処理が混ざる |
| `PRAGMA AUTONOMOUS_TRANSACTION` | 呼び出し側とは別のトランザクション。呼び出し側がまだ確定していない書き込みは見えない。呼び出し側が取り消しても、こちらの書き込みは残る |
| `SYSDATE` / `SYSTIMESTAMP` | DB サーバの時刻とタイムゾーン。`SYSDATE` は秒まで。`TRUNC(SYSDATE)` はその日の 0 時 |
| 順序（`NEXTVAL`） | 取り消しても番号は戻らない。欠番ができる。`CACHE` があれば再起動でも飛ぶ |
| trigger | 書き込んだ routine の原文には現れないが、同じトランザクションの中で動く。trigger の例外は元の DML を失敗させる。`WHEN` 句と `UPDATE OF <列>` で発火が絞られる。MERGE は INSERT と UPDATE の両方の trigger を発火させうる |
| `FORALL … SAVE EXCEPTIONS` | 失敗した行を飛ばして続け、最後に ORA-24381 を上げる。成功した行は残る |
| 動的 SQL（`EXECUTE IMMEDIATE`） | DDL（`TRUNCATE` を含む）は、その前後で暗黙に COMMIT する |
| 数値の代入 | 桁の指定がある変数・列（`NUMBER(18,2)`）への代入は、小数を丸め、整数部があふれると ORA-06502 / ORA-01438 |
| package の変数 | セッションごとに持ち、呼び出しをまたいで残る。接続プールでは、前の利用者の値が残りうる |
